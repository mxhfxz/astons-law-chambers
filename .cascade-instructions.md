# Cascade Instructions - Astons Law Chambers

## Project Overview

**Project Name**: Astons Law Chambers
**Framework**: Mast Framework v2.4 by No-Code Supply Co
**Docs**: https://www.nocodesupply.co/mast/docs

This project is a Webflow-based website for Astons Law Chambers, built using the Mast framework. External JavaScript and CSS assets are hosted on GitHub and served through jsDelivr CDN.

## Tech Stack

- **Frontend**: Webflow (visual builder)
- **Framework**: Mast Framework v2.4
- **Asset Hosting**: GitHub (public repository)
- **CDN**: jsDelivr
- **Build Tool**: Terser (for JavaScript minification)
- **Version Control**: Git

## Coding Standards

### Mast Framework Conventions

Follow all Mast framework class naming conventions as documented in `mast-framework.md`:

- **Base classes**: No prefix (e.g., `section`, `container`, `row`, `col`)
- **Utility classes**: Prefix `u-` (e.g., `u-bg-primary`, `u-mb-sm`)
- **Custom classes**: No prefix (e.g., `blog-card`, `footer-social_link`)
- **Combo classes**: Prefix `cc-` (e.g., `nav-link cc-cta`, `section cc-footer`)

### Naming Rules

- Lowercase only
- `-` between words within a single concept: `u-bg-primary`
- `_` between context levels within a component: `nav-dropdown_content`

### 80/20 Rule

Mast handles approximately 80% of any site using its default classes and components. The remaining 20% is intentional custom code. Do not extend or modify Mast's defaults — work within them.

### Class Logic Flow

1. Before creating any layout, check whether a Mast `row` and `col-lg-x` structure can achieve it.
2. Only create a custom flex div if the Mast grid cannot achieve the layout.
3. If more than 4 utility classes are needed on one element, suggest a custom class instead of stacking utilities.

If code can be placed directly into the project, do so. If not, state exactly where to place it and what to paste — then pause and wait.

## Decision Logging

Every decision made during development is logged to `DECISION_LOG.md` in the project root.

## Deployment Workflow

1. Make changes to source files in `src/`
2. Run build script to generate minified files in `dist/`
3. Commit and push to GitHub
4. jsDelivr automatically updates within seconds
5. Update Webflow custom code references if needed

## Critical Rules

1. NEVER use native Webflow Paragraph, Container, Section, or Column blocks. Use plain div blocks with Mast classes.
2. Use tree hierarchy with cc- combo classes for variants.
3. Never program in parallel to existing code. Never create duplicates.
4. Pause and wait when an action requires a manual step that cannot be completed automatically.
