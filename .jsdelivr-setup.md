# jsDelivr Setup and Configuration

This document contains the jsDelivr CDN configuration for the Astons Law Chambers project.

## Repository Requirements

- **Must be public** (jsDelivr only serves public repositories)
- **Standard package.json** for npm-style access
- **Dist folder** with built/minified assets
- **Semantic versioning** in package.json

## Directory Structure

```
astons-law-chambers/
├── src/           # Source files (JavaScript, CSS)
├── dist/          # Built/minified files (CDN serves these)
├── package.json   # npm/CDN metadata
└── README.md      # Project documentation
```

## CDN URL Patterns

### For Files in dist/
```
https://cdn.jsdelivr.net/gh/[USERNAME]/[REPO]@[BRANCH]/dist/[FILENAME]
```

### For Root Files
```
https://cdn.jsdelivr.net/gh/[USERNAME]/[REPO]@[BRANCH]/[FILENAME]
```

### NPM-style Access
```
https://cdn.jsdelivr.net/npm/[PACKAGE_NAME]@[VERSION]/[FILE]
```

## Build Process

### JavaScript Minification
```bash
npm run build
```

This runs terser to minify JavaScript files from `src/` to `dist/`.

### Build All Assets
```bash
npm run build:all
```

Builds all JavaScript and CSS assets.

## Versioning Strategy

- Use semantic versioning (MAJOR.MINOR.PATCH)
- Update package.json version before releases
- Tag releases in Git for version-specific CDN access
- Use `@main` for latest development version

## Cache Busting

jsDelivr caches files permanently based on the URL. To force cache invalidation:
1. Update the file version in the filename (e.g., `site-v2.min.js`)
2. Or use Git tags with specific versions

## Testing CDN Access

To test if jsDelivr is serving your files:
```bash
curl https://cdn.jsdelivr.net/gh/[USERNAME]/[REPO]@main/dist/[FILENAME]
```
